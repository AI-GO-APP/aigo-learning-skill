這份手冊怎麼用

不會程式也能開始。先照課前準備安裝，之後找到你的情境，貼那段話，回答 AI 的問題就好。

  1. 第一次使用，先照本章準備訂閱、協作工具與工作區；其他工具和設定由 AI 帶你完成。
  2. 安裝好學習版後，每次開啟 AI-GO-Learning 工作區，說清楚要做哪個作品；換題目可開新對話。
  3. 複製提示詞，把【】換成自己的話。講不清楚也沒關係，請 AI 一題一題問，或列兩三個做法讓你選。
範例提示詞學生貼給自己的 AI
我沒有程式經驗。請用白話帶我開始，需要我動手的地方講清楚，一次只給下一步。聽不懂時我會說「用白話再講一次」；需要選做法時，請說明每種做完會看到什麼。
完成後應看到：知道從哪裡開始、怎麼貼提示詞；不用先學會程式或背指令。

還沒安裝，先從這裡開始

這一頁的提示詞可以先貼到一般 Claude／ChatGPT 網頁；先取得能協作本機資料夾的工具。

第一則對話：貼 repo 網址

在剛開啟的本機練習資料夾貼這段。下載安裝、版本與完整性檢查交給 AI 帶你做。

  2. Claude Code 放 .claude/skills/；Codex 放 .agents/skills/。入口直接在 aigo-learning/SKILL.md。
  3. 安裝後開新對話；Claude Code 用 /aigo-learning，Codex 用 $aigo-learning。

免費工具由 AI 協助準備

不用先記 Python、uv、Node.js 指令。先檢查已有環境，再補缺項。

  1. Python 用來執行平台工具，uv 管理工具相依，Node.js 處理網站與前端檢查。
  2. 先讓 AI 回報版本與缺項；安裝前說明變更，已有版本不直接覆蓋。
  3. 遇系統權限或下載畫面，由你依一步一步說明操作；需要 Git／GitHub 時才另補。
範例提示詞學生貼給自己的 AI
我沒有程式經驗。請檢查作業系統、Python、uv、Node.js，回報版本及缺項，再說明免費工具的安裝步驟。經我確認後協助安裝缺項，不覆蓋既有版本或全域設定。需要我點畫面時一次給一步；尚未準備好也先帶我做需求，不登入或改平台。
完成後應看到：工具有實際檢查結果；缺少項目與下一步明確，不會被要求手寫程式。

設定交給 AI，密碼自己填

助教會在開通時提供公司空間網址、學員 email、專屬群組名稱及 id。你不用自己找或猜 id。

  1. 把助教提供的非機密開通資料給 AI；缺少時先請助教補齊。
  2. AI 建資料夾與設定檔；你不必手編 JSON。已有設定先核對，不覆蓋。
  3. AI 告訴你憑證檔的完整路徑與開啟方式。你在本機自己填密碼，填好再回覆。
範例提示詞學生貼給自己的 AI
請先問我助教提供的空間網址、email、群組名稱及 id，再用學習版的 learning_bootstrap 建非機密設定。已有檔案先停下核對。告訴我如何在本機開啟憑證檔並自行填密碼，不讀出內容；等我說填好了，再只核對租戶與登入身分，不建立 App。
完成後應看到：資料夾與設定已建立；有效空間、登入身分及助教提供的群組吻合。

白話名詞：空間與權限

看不懂時直接問，不必背縮寫。一般版與學習版是技能用法，並非兩套 AI GO 平台。

名詞白話怎麼看
一般版／學習版一般版以實際專案交付為主；學習版同時練習理解與修改。
租戶你的公司／課程空間；網址由助教提供。
roles group助教開好的專屬權限群組；名稱及 id 會一起提供。
Custom App本課用來做需登入的內部工作系統。
Hosted App（HostApp）本課用來做對外官網或預約申請入口的網站服務。
資料引用列出這個 App 可以讀寫哪些資料；不是有表就能全部使用。
範例提示詞學生貼給自己的 AI
請用我的官網與內部清單，白話解釋我不懂的名詞，各給一個例子，再請我用自己的話說一次；不操作平台。
完成後應看到：知道客人的網站入口與自己的內部工作入口不同。

白話名詞：工具與錯誤

AI 說出英文名詞時，可以要求它立刻翻成你正在做的事情。

名詞白話怎麼看
SDK／Server Action平台工具包／在伺服器執行的工作；資料授權由伺服端檢查。
published已發布；可能仍是舊版，要核對本次新行為。
401／403登入驗證沒過／沒有這個操作權限；不能借助教帳號繞過。
Deploy Token指定 App 的部署金鑰，只放自己的 GitHub Actions secret。
GitHub Actions／CI幫你自動檢查與部署的流程；由 AI 協助產生設定。
commit／health程式版本識別／網站回報目前運行版本的檢查入口。
範例提示詞學生貼給自己的 AI
請把目前看到的技術詞與錯誤翻成白話，說明我該看哪裡及下一步；未確認就標未知，不印憑證、不改權限。
完成後應看到：能分清「登入問題」「權限問題」與「這次更新是否真的上線」。

先確認兩個作品的用途

用同一個店家情境：客人看服務、送出申請；內部人員確認與追蹤。

  1. 內部系統：給自己或工作人員使用的處理清單，先做一條小流程。
  2. 對外網站：讓客人不用課程帳號就能看官網、填申請；使用 Hosted App。
  3. 第一版做申請型預約，待店家確認；自動保留名額、付款與會員歷史另列進階規格。
範例提示詞學生貼給自己的 AI
用學習版。我想做【哪一種店家】的【官網／預約申請】，另外有我自己看的處理清單，因為【想改善什麼】。先幫我畫出客人到店家的流程，分清哪些給客人看、哪些只給我看，存成需求草稿；先不要做 App。
完成後應看到：兩個作品各給誰用、用什麼資料及如何串接已說清楚。

說清楚一個小需求

先選一個可以完整驗證的小問題。可用虛構店家、自用情境或熟悉產業。

  1. 說明誰會用、目前怎麼做、卡在哪裡，以及完成後希望改變什麼。
  2. 先用白話描述，讓 AI 整理已知事實、推測與待問事項。
  3. 授權 AI 儲存 docs/requirements.md；此時只整理文件，不改平台。
範例提示詞學生貼給自己的 AI
用學習版。我想做【哪個作品】，給【誰】使用，現在【怎麼做、哪裡不方便】，做完希望【看到什麼結果】。請幫我整理並存成 docs/requirements.md。講不清楚的地方一題一題問；先不寫程式或建立 App。
完成後應看到：有一份讀得懂的需求文件；本次要做與暫時不做的範圍清楚。

把需求變成可確認的規格

規格同時涵蓋內部系統與對外網站；你先確認範圍，再開始實作。

  1. 列兩個 App 的畫面、欄位、資料來源、操作身分與公開／內部界線。
  2. 定義正常、缺值、錯誤、重送及「申請不等於已確認名額」的行為。
  3. AI 儲存 docs/spec.md 與 docs/acceptance.md；你確認前不建立 App。
範例提示詞學生貼給自己的 AI
用學習版。先別動手，請把剛才的需求整理成「有哪些畫面、資料從哪來、誰看得到、做完怎麼檢查」。不懂的地方用例子講給我聽，需求和驗收表幫我存好；我確認前先不要做 App。
完成後應看到：你能逐項說明畫面與規則；未知欄位／權限已列出，驗收有預期值。

確認規格後才開始實作

你確認的是這次範圍。若途中新增功能，先更新規格與驗收，不讓 AI 順手擴大。

  1. 逐項看過規格，指出要改的地方；不要只回「都可以」而沒理解。
  2. 確認本次最小流程與允許的操作；發布是否包含在內要說清楚。
  3. 保留規格版本，之後依同一版驗收。
範例提示詞學生貼給自己的 AI
用學習版。剛剛的規格我確認了：先做內部清單和單筆更新，再做客人的官網與申請表，不做付款或自動保留名額。請先說最小的幾個步驟，帶我選助教提供的專屬群組並核對；先不要上線。
完成後應看到：實作範圍、規格版本、資料與發布界線都有紀錄。

內部 App：立即核對群組

助教會提供群組名稱與 id。這一步在資料與程式進入內部 App 前完成。

  1. 建立內部 Custom App 時，手動選助教提供的專屬群組；缺資料就請助教補齊。
  2. 建立後立即核對公司空間、App id、internal 模式與群組，再登錄別名。
  3. 未確認群組前，不匯入、同步、編譯或發布；不要拖到上線前。
