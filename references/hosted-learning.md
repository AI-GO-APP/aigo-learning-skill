# 一個情境，內部系統＋對外網站

學習版安排練習順序；技術與整合由 Builder 負責。以服務店家介紹／預約申請／內部跟進為主例，可換官網、詢價或報名，不預設學員有公司題目或要接案。

1. 白話確認誰用、公開頁面與內部資料、要解決的問題；Builder 完成產品線、規格、資料與必要授權判斷。
2. 內部 Custom App 做處理清單，建立時學員手動選助教群組，立即回讀；再由 Builder 開發、驗證與依授權發布。
3. 對外 Hosted 先本機做官網、申請表與結果，再由 Builder 接同一份確認過的資料來源。基本題是申請，送出不等於名額保留。
4. Builder 處理建立、本人 App id／slug、資料引用、環境變數、公開設定與伺服端權限；學習版在每個決定前解釋結果並安排改例。
5. 每次 Hosted 平台寫入前用 learning_scope.py --workspace <工作區> --app <別名> --kind hosted 核對。公開網站不掛內部群組，但不能把內部清單與整張資料公開。
6. Hosted repo／Actions 做法與 resources/hosted-ci.py、resources/hosted-deploy.example.yml 由 Builder 提供。學生自己登入 GitHub、放 App 專用部署金鑰；平台帳密不進 GitHub。
7. 核對 /health commit、匿名頁面、虛構申請進內部同一筆資料、重送與錯誤情境；明列未驗證，不以 CI 通過代替業務與授權驗收。

需要會員、歷史紀錄、付款、自動確認或名額並行鎖時，請 Builder 判斷技術與授權，另確認本次練習範圍，不假裝基本版已包含。
雙作品是課程路徑，實際產品線仍由 Builder 依需求判斷；不為配合教材硬塞錯誤平台能力。

> 用學習版。我想做【服務官網＋預約申請】和內部處理清單。請搭配 Builder 完成技術、資料與整合判斷，用白話分小步帶我；先確認兩個入口、資料界線及驗收。先本機原型，不部署，未確認的功能列待確認。
